# שלב 3 · פיתוח

> הצוות מגדיר את מפת הדרכים המפורטת של המיזם ומתקדם מרעיון לביצוע מעשי ולהוכחת ערך מהירה (POV). בשלב זה מפותחת גרסת מוצר ראשונית (MVP) ונבחנת ההיתכנות הטכנולוגית והעסקית.

## מטרה

אחרי ש[הגדרת המיזם](../02-הגדרת-המיזם/README.md) הניבה בריף מיזם ושותף מוביל, השלב הזה מתרגם את הרעיון למפת דרכים ממשית ולהוכחת ערך בשטח — לא רק על נייר. המתודולוגיה כאן ניטרלית-כלים: כל צוות ושותף מוביל בוחר את השיטה הספציפית המתאימה למיזם (Design Thinking, Lean Startup וכו'), אך שלושת תתי-השלבים ותוצריהם מחייבים.

## עיקרון מרכזי: MVP הוא לא "גרסה חלקית" — הוא כלי לתשובה לשאלה אחת

> **MVP — המינימום הנדרש כדי שהמשתמש יגיד "WoW, כזה אני צריך".**

שאלת ה-MVP היא ההשערה הקריטית ביותר שעליה עומד או נופל המיזם. היא נגזרת מהיעד העסקי ומהבעיה שזוהתה בשלב החקר, ממוקדת ובדידה, בעלת קריטריון הכרעה ברור מראש, ובת-מענה בכמה שבועות. השרשרת המלאה: **שאלת ה-MVP → גרסת MVP מינימלית → הוכחת ערך (POV)**.

## מעבר לשלב הבא

הוכחת ערך (POV) שעברה בהצלחה ואושרה — עוברת ל[יישום ופריסה: Production](../04-pmf-production-scale/README.md#תת-שלב-א--production-mvp), ומשם ל-PMF ול-Scale. אם התשובה על שאלת ה-MVP שלילית, חוזרים לזיקוק הבעיה מחדש (ב[הגדרת המיזם](../02-הגדרת-המיזם/README.md)) או להגדרת הפתרון מחדש (בתוך שלב זה).

> אם המיזם כולל טרנספורמציה של מערכת ליבה טכנולוגית ותיקה (לא רק בניית מוצר דיגיטלי חדש) — ראו גם את הנספח [שיטת פיתוח אג'נטי ו-ADR](../05-שיטת-פיתוח-אגנטי-וadr/README.md), שמפרט את המתודולוגיה הטכנית המתאימה למקרה הזה.
