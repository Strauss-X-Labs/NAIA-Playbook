## תת-שלב א׳ — Production (MVP)

### מהות

מעבר לפיתוח מוצר עובד ויציב בסביבת ייצור אמיתית — בניית ה-AI Stack המלא, שילוב ארכיטקטורת מערכת קבועה (ראו [3.2 עיצוב המוצר וארכיטקטורה](../03-mvp-poc/02-עיצוב-המוצר-וארכיטקטורה.md)) והשקת גרסה ראשונית מתפקדת המוכנה לשימוש ראשון של משתמשי קצה.

בשלב זה, צוות הליבה של המטה עובר למוד ליווי לצורך וידוא התקדמות לקראת יצירת ה-Impact שהוגדר.

### שאלות עבודה מרכזיות

- מי הם "משתמשי הקצה הראשונים" ומהו היקף ההשקה הראשונית? (Onboarding, תמיכה, נתונים)
- כיצד מוגדר "מוד הליווי" של צוות הליבה — גבולות האחריות והממשק מול המיזם?
- מהו קריטריון ה"תפקוד המלא והתקין בסביבת ייצור" — כיצד נמדד ומי מאשר את העמידה בו?

### פעילויות מרכזיות

- בניית ה-AI Stack המלא לסביבת ייצור
- שילוב ארכיטקטורת מערכת קבועה ויציבה
- הגדרת תהליכי Onboarding למשתמשים הראשונים
- הקמת מנגנוני תמיכה ושירות לקוחות
- מעבר צוות המטה ממוד ליווי צמוד (Hands-on) למוד ליווי מרחוק (Advisory)

### קריטריון מעבר מ-Production ל-PMF

- [ ] **תפקוד מלא ותקין בסביבת ייצור אמיתית** — המוצר יציב, נגיש ומשרת משתמשי קצה בפועל

## תת-שלב ב׳ — PMF (Product/Market Fit)

### הגדרה

> **PMF — הרגע שבו אנחנו יודעים שהמוצר מתאים בול לשוק.**

בניגוד ל-MVP (שבודק אם משתמש בודד אומר "WoW, אני צריך את זה"), PMF בודק אם התופעה חוזרת **בעקביות ובסקייל קטן**: האם משתמשים חוזרים למוצר, ממליצים עליו, ומוכנים לשלם/להתחייב עליו — לא רק מתלהבים בהדגמה חד-פעמית.

### מה קורה בשלב הזה

- הרצת ה-MVP (שעבר Production) מול קבוצת משתמשים/שותפים אמיתית.
- ריצות משוב שיטתיות עם משתמשים — ראו תהליך איסוף המשוב בטמפלייט למטה.
- מדידת אינדיקציות PMF: שימור (Retention), הפניות אורגניות/ביקוש פאסיבי, נכונות לשלם/להתחייב, עומק השימוש (לא רק כניסה חד-פעמית).
- ביצוע התאמות במוצר על בסיס הממצאים.
- **החלטה בינארית בפועל:** יש PMF → ממשיכים לתת-שלב ג׳ · [Scale](#תת-שלב-ג--scale-for-impact). אין PMF עדיין → חוזרים ללולאת ה-Lean UX (Think → Build → Measure → Learn) בתוך [פיתוח](../03-mvp-poc/README.md), לא ממשיכים הלאה מתוך אינרציה.

### טמפלייט — מדידת PMF

> **הוראות שימוש:** מלאו את הטבלה על בסיס נתוני שטח בפועל. שאלת הבסיס של PMF היא: "כמה תאוכזבו אם המיזם לא יהיה זמין עוד?" — 40%+ תשובות "מאוד מאוכזב" מחוות PMF.

**מדדי אימוץ ושימוש:**

| מדד | כלי מדידה | תדירות | יעד | מצב נוכחי |
|---|---|---|---|---|
| מספר משתמשים פעילים (DAU/MAU) | Analytics | שבועי | | |
| שיעור שימור (Retention) | Analytics | חודשי | | |
| שיעור ביקוש פאסיבי (Inbound) | CRM / מדדי תפעול | חודשי | | |
| שביעות רצון משתמשים (NPS / CSAT) | סקרים | רבעוני | | |
| נכונות הטמעה של לקוחות יעד | ראיונות / סקרים | רבעוני | | |

**תהליך איסוף משוב:**

| שאלה | תשובה |
|---|---|
| ממי אוספים משוב (סגמנטים)? | |
| באילו כלים ושיטות? (סקרים, ראיונות, נתוני שימוש...) | |
| באיזו תדירות? | |
| מי אחראי לניתוח ולהפקת לקחים? | |
| כיצד מתרגמים ממצאים לשינויים במוצר? | |

### Gate — מעבר מ-PMF ל-Scale

- [ ] יש עדות עקבית (לא חד-פעמית) לכך שהמוצר פותר בעיה אמיתית עבור הפרסונה שהוגדרה
- [ ] יש נכונות ממשית מצד המשתמשים/השותף להתחייב (תקציב, זמן, אינטגרציה) — לא רק "מעניין"
- [ ] ההנחה הליבה מה[הגדרת המיזם](../02-הגדרת-המיזם/02-רעיונאות-AI.md) אומתה בפועל, לא רק בתאוריה
- [ ] **המוצר תואם לצרכי השוק ונותן את הערך המצופה** — נתמך במדדי אימוץ ומשוב מוכח
- [ ] **ביקוש פאסיבי ונכונות הטמעה** — לקוחות יעד מגלים עניין ומוכנות ללא דחיפה פעילה

**המשך:** תת-שלב ג׳ · Scale for Impact, בהמשך מסמך זה.

## תת-שלב ג׳ — Scale for Impact

### מהות

שכלול המודל האופרטיבי והפצה רחבה של הפתרון כדי לייצר אימפקט לאומי ומדיד ב-Scale. זהו תת-השלב האחרון בתהליך — מימוש מלא של יעד ה-Impact שהוגדר בראשית הדרך, לאחר שתת-שלב ב׳ · [PMF](#תת-שלב-ב--pmf-productmarket-fit) אומת בפועל.

### שאלות עבודה מרכזיות

- מהו יעד ה-Impact הלאומי ומהם המדדים למדידתו — בהתאם למפת הדרכים?
- מי קובע שיעד ה-Impact הושג?

> **הערה חשובה:** יעד ה-Impact צריך לבוא לידי ביטוי כבר משלב [מפעל הבעיות](../01-מפעל-הבעיות/README.md) ולקבל חידוד ודיוק בשלב [חקר הבעיה](../02-הגדרת-המיזם/01-חקר-הבעיה.md). מדדי ה-Impact בשלב ה-Scale צריכים להיות **אותם מדדים** שהוגדרו בתחילת התהליך ושדוייקו ב[מפת הדרכים](../03-mvp-poc/03-מפת-הדרכים-ו-gtm.md).

### פעילויות מרכזיות

- שכלול המודל האופרטיבי לפריסה רחבה
- פריסת הפתרון לכלל אוכלוסיית היעד
- מדידה שוטפת של מדדי ה-Impact
- הצגת נתוני האימפקט להנהלת המטה

### קריטריון הצלחה / סיום

- [ ] **השגת ה-Impact על פי המדדים והיעדים שהוגדרו במפת הדרכים**

> **מי קובע?** הנהלת המטה דנה בכל המיזמים וקובעת מתי מיזם השיג את מטרת ה-Impact שלו.

### טמפלייט — מדידת Impact

> **הוראות שימוש:** הגדירו את מדדי ה-Impact בהתאמה מלאה למה שהוגדר במפת הדרכים. אל תגדירו מדדים חדשים בשלב זה — דייקו את הקיימים.

| מדד Impact | הגדרה | כלי מדידה | יעד כמותי | מצב נוכחי |
|---|---|---|---|---|
| (מדד 1 — מתוך מפת הדרכים) | | | | |
| (מדד 2 — מתוך מפת הדרכים) | | | | |
| (מדד 3 — מתוך מפת הדרכים) | | | | |

**סיכום עמידה ביעדים:**

| יעד | האם הושג? | הערות |
|---|---|---|
| | כן / חלקית / לא | |
| | כן / חלקית / לא | |

תוצאות מדידת ה-Impact מוזנות בחזרה ל[מדדי משפך (Funnel Health)](../01-מפעל-הבעיות/ניהול-משפך-ותיעדוף-דינמי.md) של מפעל הבעיות, כדי לסגור את הלולאה: האם הבעיה המקורית אכן נפתרה בסקייל לאומי.

### תפקיד המטה בשלב זה

מדידת Impact ואישור הגעה ליעד — הנהלת המטה דנה בכל המיזמים הנמצאים ב-Scale וקובעת מתי הושגה מטרת ה-Impact.

> אם המיזם כולל מערכות Legacy/ליבה — כאן נכנס במלואו הנספח [שיטת פיתוח אג'נטי ו-ADR](../05-שיטת-פיתוח-אגנטי-וadr/README.md): ה-Business Wiki שנבנה בשלב הפיתוח הופך למקור אמת מתמשך, לא מסמך חד-פעמי.
