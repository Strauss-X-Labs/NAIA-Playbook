# ניהול פרמטרים והיסטוריית שינויים

> עיקרון חוצה-תחומים: בכל מקום בכור ההאצה שמוגדר בו **פרמטר** — ערך מספרי או קטגורי שהנהלת המטה (או Domain Lead) רשאית לעדכן מעת לעת (יעד, אחוז, תדירות, סף עלות, יחס המרה וכו') — הערך הנוכחי לבדו אינו מספיק. יש לנהל את הפרמטר כ**"כרטיס פרמטר"** בתוך הוויקי, עם היסטוריית שינויים מלאה.

## למה זה חשוב

בלי היסטוריה, השאלה "למה שינינו את היעד השנתי מ-5 ל-8 בעיות בשנה שעברה?" נשארת בלי תשובה. זה סותר במישרין את [עיקרון התיעוד](README.md#עיקרון-העל-תיעוד-הוא-חובה-לא-אופציה) הכללי של הריפו — אם החלטה על ערך פרמטר לא מתועדת ולא נשמרת, נוצרת בדיוק אותה "אמנזיה ארגונית" שהעיקרון הזה נועד למנוע.

## מהו "כרטיס פרמטר"

כל פרמטר ניתן לעדכון מתועד עם ארבעה רכיבים:

- **הערך הנוכחי**
- **בעל הפרמטר** — מי מוסמך לשנות (הנהלת המטה / Domain Lead, תלוי בפרמטר)
- **תאריך העדכון האחרון**
- **טבלת היסטוריית שינויים:**

| תאריך | ערך קודם | ערך חדש | מי שינה | נימוק |
|---|---|---|---|---|
| | | | | |

## איפה זה חי

כרטיס הפרמטר נשמר **בתוך הקובץ שבו הפרמטר מוגדר לראשונה** — לא בקובץ מרכזי נפרד לכל הפרמטרים. זה עקבי עם עקרון [קישור, לא שכפול](תפיסת-ה-wiki.md) — כל פרמטר חי במקום הטבעי שלו, ולא נשכפל למרשם גלובלי שידרוש סנכרון כפול.

## דוגמאות לפרמטרים קיימים בריפו הכפופים לעיקרון זה

- יעד שנתי לבעיות שהופכות לפתרון בפועל, ויחסי ההמרה בין שלבי המשפך (כולל סטים שונים לפי מורכבות בעיה) — ראו [ניהול משפך ותיעדוף דינמי](../01-מפעל-הבעיות/ניהול-משפך-ותיעדוף-דינמי.md#פרמטרי-המשפך)
- תמהיל הסיכון (70%/30%) — ראו [תמהיל-סיכון-ותשואה](../01-מפעל-הבעיות/תמהיל-סיכון-ותשואה.md)
- תדירויות ומכסות עלות של הרצות סוכני AI — ראו [בקרת עלות והרצות סוכני AI](../01-מפעל-הבעיות/בקרת-עלות-והרצות-סוכני-AI.md)
- חלון המענה ל-RFI — ראו [חקר הבעיה](../02-הגדרת-המיזם/01-חקר-הבעיה.md)
- משקלות קריטריוני התיעדוף (אימפקט / אסטרטגי / ישימות / סיכון) — ראו [דרישות-סף-וקריטריוני-תיעדוף](../01-מפעל-הבעיות/דרישות-סף-וקריטריוני-תיעדוף.md#פרמטר-משקלות-קריטריוני-התיעדוף)

> **הערה:** נכון להיום כרטיס הפרמטר המלא (כולל טבלת היסטוריה) מומש במקומות שצוינו לעיל. פרמטרים נוספים שיתגלו בריפו יעברו לאותו מבנה בהדרגה.
