# תהליך זיהוי, תיוג ותיעוד בעיה

## כרטיס בעיה — השדות המובנים

כל בעיה שנכנסת לרשימה מקבלת **כרטיס בעיה** מובנה (תבנית מלאה: [06-כלים-ותבניות/כרטיס-בעיה-תבנית.md](../06-כלים-ותבניות/כרטיס-בעיה-תבנית.md)):

| שדה | תיאור |
|---|---|
| שם הבעיה | קצר וברור |
| ניסוח בעיית חיים | משפט אחד: מי סובל, ממה, ומה ההשלכה |
| אזור אתגר לאומי | אחד מ-9 התחומים (ואזור משני אם רלוונטי) |
| אוכלוסייה שנפגעת | ספציפית ככל האפשר |
| גוף ממשלתי/ציבורי רלוונטי | מי יכול להיות "בעל הבית" |
| אנשי קשר רלוונטיים | גורמים בעלי ידע או השפעה על הבעיה — שם, תפקיד, ארגון, דרך התקשרות |
| מקור הבעיה | קישור ישיר |
| ראיות ממקורות | ציטוטים, נתונים, ממצאים מרכזיים |
| מדד תוצאה אפשרי | מה ישתפר, בכמה, לאיזו אוכלוסייה |
| חסמים טכנולוגיים | חוסר יכולת/תשתית AI מתאימה, איכות מודלים קיימים, קושי אינטגרציה עם מערכות קיימות |
| חסמי רגולציה | חקיקה חוסמת, הרשאות נדרשות, פרטיות, רגולטור ייעודי |
| חסמי דאטה | זמינות, איכות, בעלות, הרשאות גישה |
| חסמים אחרים | תהליך / תקציב / אמון / הטמעה / תיאום / כוח אדם / נגישות |
| גורמים מאפשרים ומאיצים | מה כבר קיים ויכול לקדם או להאיץ פתרון — תמיכה ניהולית, תשתית זמינה, שותף מעוניין, תקדים דומה שהצליח |
| סיכונים אפשריים | סיכונים צפויים למיזם/לפתרון — טכנולוגי / רגולטורי / ארגוני / פוליטי |
| חוזרת ביותר ממקור אחד? | כן/לא + פירוט |
| פוטנציאל AI | נמוך / בינוני / גבוה + הסבר |
| למה AI רלוונטי | מנגנון ספציפי |
| שאלות פתוחות | מה עוד צריך לברר |
| רמת בשלות להעמקה | נמוכה / בינונית / גבוהה |

**תיוגי חובה:** מקור הבעיה (ממשלתי/מחקרי/שטח/טכנולוגי/אחר) · תוקף/שכיחות (חד-פעמי/חוזר/מבני) · רמת סיכון (low/high) · סוג (B2G/B2B/B2C/תשתית).

## כלי מרכזי — הפרומפט למציאת בעיות

המטה פיתח **פרומפט חקר מובנה** לסוכני AI לסריקה שיטתית של 27+ מקורות מידע, חילוץ בעיות אפשריות ובניית טבלה מובנית.

**עקרונות הפרומפט:** לא לחפש פתרונות — לחפש בעיות חיים קונקרטיות עם ראיות ומדדים · להבחין בין סימפטום לשורש · להעדיף בעיות שחוזרות בכמה מקורות · לסמן מקור חלש שדורש תיקוף.

**תוצר הפרומפט:** טבלת בעיות מלאה לכל אזור אתגר בנפרד — כל הבעיות הרלוונטיות שנמצאו, ללא מספר יעד קבוע מראש ובלי לצפות לכמות זהה בין אזורים · לכל בעיה מקור אחד לפחות (עדיפות לשניים+) · סימון בעיות מבטיחות להעמקה, ללא מכסה קבועה · חלוקה לפי אזורי אתגר · המלצה לאן לא להשקיע מאמץ נוסף.

הפרומפט המלא: [06-כלים-ותבניות/פרומפט-חקר-בעיות.md](../06-כלים-ותבניות/פרומפט-חקר-בעיות.md).

## חקר שורש — שייך לשלב הגדרת המיזם

חקר שורש מובנה ומעמיק — Five Whys, Problem Tree, System Mapping, ניתוח חסמים, מיפוי מסע משתמש, חקר דאטה, חקר AI Fit, חקר שוק וחקר ישימות — **אינו מתבצע בשלב מפעל הבעיות**. הוא אחד השלבים המרכזיים של [חקר הבעיה](../02-הגדרת-המיזם/01-חקר-הבעיה.md) ב[הגדרת המיזם](../02-הגדרת-המיזם/README.md) — תהליך פורמלי ומובנה בן 6 שלבים (כולל RFI פתיחה) — ומתבצע רק **לאחר** שבעיה נבחרה ועברה תיעדוף.

במפעל הבעיות עצמו נעשית רק בדיקה ראשונית וקלה, על דאטה קיים בלבד — האם בכלל ברור שמדובר בשורש ישים ולא רק בסימפטום — כחלק ממבחן "האם אפשר לנקד" (ראו [שלב 0 באלגוריתם הניקוד](אלגוריתם-ניקוד-ותיעדוף.md#שלב-0-האם-בכלל-אפשר-לנקד)).
