# תבנית: מרשם שכבת הניהול

> העתיקו קובץ זה אל `כורי-בינה/<שם-הכור>/01-מפעל-הבעיות/מרשם-שכבת-הניהול.md`. הכללים המלאים: [שכבת הניהול](../01-מפעל-הבעיות/ניהול-משפך-ותיעדוף-דינמי.md#שכבת-הניהול-management-layer).

**המרשם הוא המקום היחיד שבו נרשמות החלטות שכבת הניהול.** מכאן אפשר לראות אילו הוראות ניתנו, מי נתן אותן ועד מתי הן בתוקף. **החלטה שלא נרשמה כאן אינה מחייבת את הסוכנים.**

## סוגי ההחלטות

| סוג | דוגמה | היקף | תוקף |
|---|---|---|---|
| **מיקוד תחומי** | "בחודשיים הקרובים נתמקד בביטחון לאומי" | אזור אתגר אחד או יותר | תאריך סיום — חובה |
| **הכוונת תמהיל** | "נרצה לפחות בעיה אחת מתחום ההזדקנות השנה" | המשפך או אזור אתגר | תאריך סיום — חובה |
| **ג'וקר** | אישור מעבר של בעיה להגדרת המיזם חרף הציון | בעיה אחת (`P-nnn`) | עד מעבר השער, או תאריך שנקבע בהחלטה |
| **החלטה בניגוד לנתונים** | Override לרצועת החלטה או לדירוג | בעיה אחת (`P-nnn`) | עד הניקוד הבא של הבעיה, או תאריך שנקבע |

**מה לא נרשם כאן:** שינוי ערך של פרמטר, כמו משקלות או יעד שנתי. שינוי כזה נרשם בכרטיס הפרמטר עצמו ([ניהול פרמטרים](../00-חזון-ועקרונות/ניהול-פרמטרים-והיסטוריית-שינויים.md)).

## המרשם

| מזהה | תאריך החלטה | סוג | ההוראה | היקף | מי החליט | בתוקף מ- | בתוקף עד | נימוק | מקור | סטטוס |
|---|---|---|---|---|---|---|---|---|---|---|
| ML-001 | | | | | | | | | | בתוקף |

**הסבר השדות:**
- **מזהה:** `ML-nnn`, רץ ולא ממוחזר.
- **ההוראה:** ניסוח אחד שאפשר לפעול לפיו. לא "לתת עדיפות לביטחון" אלא "בחירת המועמדת הבאה תעדיף בעיות מאזור ביטחון לאומי".
- **מי החליט:** שם ותפקיד.
- **בתוקף עד:** תאריך, או בג'וקר אירוע הסיום ("עד מעבר שער G").
- **נימוק:** חובה. בג'וקר הנימוק כולל את הציון בעת ההחלטה, ולמה בכל זאת יש לבעיה פוטנציאל מערכתי שעדיין לא מנוסח במדדים קיימים. מקשרים לתיק האישור.
- **מקור:** קישור לסיכום הדיון או לתיק האישור.
- **סטטוס:** `בתוקף` · `פג` · `בוטל — ML-nnn`.

## כללים

1. **רושמים מיד אחרי ההחלטה.** [`pf-decision-logging`](../.claude/skills/pf-decision-logging/SKILL.md) מכין את הרשומה, ומי שהחליט מאשר אותה.
2. **אין רשומה בלי מי שהחליט, נימוק ותאריך סיום.** החלטה בלי תאריך סיום אינה "מוגבלת בזמן", ולכן לא נרשמת.
3. **לא מוחקים ולא עורכים רשומה.** ביטול, הארכה או שינוי נרשמים כרשומה חדשה שמפנה לקודמת, ובסטטוס של הקודמת כותבים `בוטל — ML-nnn`.
4. **סוכנים קוראים רק רשומות בסטטוס `בתוקף` שהתאריך של היום נמצא בטווח שלהן.** כך עובד [`pf-next-candidate`](../.claude/skills/pf-next-candidate/SKILL.md).
5. **בכל [Funnel Review](../.claude/skills/pf-funnel-review/SKILL.md)** מוצגות ההחלטות שבתוקף, ואלה שפג תוקפן מאז הסקירה הקודמת. החלטה שתאריך הסיום שלה עבר מקבלת סטטוס `פג`.
