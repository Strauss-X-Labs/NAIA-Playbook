# תת-שלב 3.3 — מפת הדרכים (Roadmap & GTM)

## מהות

יצירת תוכנית העבודה המעשית והממוקדת: הגדרת יעדים, אבני דרך ושלבי השקה, ותכנון מדויק של היקף ה-MVP ומאפייניו. מפת הדרכים מכסה את כל נדבכי המיזם — עסקיים, תפעוליים וטכנולוגיים — לאורך כל שלבי ההתפתחות המתוכננים.

## שאלות עבודה מרכזיות

- כיצד מחלקים את המיזם לשלבי מוצר (שלב 0–4) וכמה זמן ימשך כל שלב?
- מה מגדיר כל שלב? (מטרה, הגדרת הצלחה, בעלי עניין, הצעת ערך, תכולה, שיווק, טכנולוגיה, תפעול, מדדים)
- מה נכלל ב-MVP הראשוני ומה נדחה לשלבים הבאים?
- מהו קריטריון המעבר ל-POV?

## מבנה מפת הדרכים

מפת הדרכים בנויה כמטריצה: ציר הזמן (שלבי מוצר 0–4) × ציר האפיון (12 מרכיבים אחידים לכל שלב). המעבר בין שלבים מותנה בקריטריונים מוגדרים מראש.

### 12 מרכיבי האפיון

| מרכיב | מה מגדיר המרכיב |
|---|---|
| שם השלב | כותרת מזהה וקצרה הממצה את מהות השלב |
| משך השלב | מסגרת הזמן הצפויה להשלמת השלב |
| מטרת השלב | מה השלב נועד להשיג ומדוע הוא קיים |
| איך תיראה הצלחה? | התוצאה הרצויה בסיום השלב, בשפה מדידה |
| בעלי עניין בשלב | מי מעורב, מי מחליט ומי מושפע |
| אתגרים וחסמים | הסיכונים והמכשולים הצפויים בשלב |
| הצעת הערך | הערך שהמוצר מספק למשתמש בשלב זה |
| תכולת המוצר בשלב | היכולות והרכיבים הנכללים בשלב |
| שיווק וערוצים | כיצד מגיעים למשתמשים ומייצרים אימוץ |
| טכנולוגיה | רכיבי ה-Stack והתשתית הנדרשים בשלב |
| רגולציה | שיקולים ופעולות בנושאים רגולטוריים |
| תפעול ומודל הפעלה | כיצד השירות מופעל, נתמך ומתוחזק |
| מדדים ומדידה | המדדים שלפיהם נעקוב אחר התקדמות והצלחה |

## טמפלייט — מפת הדרכים

> **הוראות שימוש:** מלאו את הטבלה עבור כל שלב מוצר. משך כל שלב נגזר מהיעדים ומתנאי המעבר. השאירו ריק שלבים שטרם הוגדרו.

| מרכיב | שאלת הכוונה | שלב 0 | שלב 1 | שלב 2 | שלב 3 | שלב 4 |
|---|---|---|---|---|---|---|
| **שם השלב** | כותרת קצרה הממצה את מהות השלב | | | | | |
| **משך השלב** | כמה זמן ימשך השלב (כולל תכנון, הכנה, ביצוע ומדידה)? | | | | | |
| **מטרת השלב** | מה המטרות שלנו בשלב הזה? מה אנחנו רוצים להשיג? | | | | | |
| **איך תיראה הצלחה?** | איך תיראה המציאות במקרה של הצלחה מלאה? | | | | | |
| **בעלי עניין בשלב** | מי בעל העניין העיקרי? (כולל כמויות אם רלוונטי) | | | | | |
| **אתגרים וחסמים** | אילו אתגרים צריך לתת להם מענה? (תקצוב, אישורים, תלות בשותפים, טכנולוגיה, רגולציה, אימוץ...) | | | | | |
| **הצעת הערך** | מה אנחנו מציעים למשתמשים בשלב הזה? מה יוצא להם מזה? | | | | | |
| **תכולת המוצר בשלב** | מה יש במוצר? (מודולים, פיצ'רים, יכולות, רכיבי Back...) | | | | | |
| **שיווק וערוצים** | איך ניצור מודעות, עניין, שימוש ואימוץ? (מדיה, מייל, כנסים, פגישות אישיות, אפליקציה, רשימות המתנה...) | | | | | |
| **טכנולוגיה** | מה נדרש טכנולוגית? (תשתיות, כלים ומערכות, פיתוח, אינטגרציות) | | | | | |
| **רגולציה** | אילו רגולטורים ופעולות רגולטוריות רלוונטיים לשלב? | | | | | |
| **תפעול ומודל הפעלה** | אילו תהליכים ובעלי תפקידים נדרשים? האם נדרשת תמיכה/שירות לקוחות? | | | | | |
| **מדדים ומדידה** | מהם המדדים בשלב? (מודעות, שימוש, מעורבות, שביעות רצון, התייעלות...) איך נמדוד? | | | | | |
