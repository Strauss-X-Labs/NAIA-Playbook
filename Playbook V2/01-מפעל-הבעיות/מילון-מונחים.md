# מילון מונחים — מפעל הבעיות

| מונח | הגדרה |
|---|---|
| כור האצה | תהליך מלא מזיהוי בעיה עד פתרון בסקייל ואימפקט |
| מפעל הבעיות | שלב-על 1: איסוף, תיקוף ותיעדוף בעיות |
| דרישת סף | תנאי חוסם כניסה — שלא מקיימים אותו לא נכנסים |
| קריטריון תיעדוף | פרמטר שמשפיע על הדירוג, לא חוסם כניסה |
| שער 0 | שער מקדים וחוסם: האם זו בעיה אמיתית ולא פתרון במסווה. אם אינו עובר, שערים 1–2 אינם נבדקים ([שערי הסף](שערי-הסף.md)) |
| התאמה מהותית ל-AI | שער 1: יכולת AI ממלאת תפקיד מהותי בטיפול בכשל מרכזי ומאפשרת שינוי משמעותי ביחס לחלופה סבירה ללא AI |
| AI קוסמטי | רכיב AI נלווה, שהסרתו אינה פוגעת מהותית בערך הנוצר; עילת פסילה בשער 1 |
| קשר לאימפקט | שער 2: קיים מסלול סיבתי סביר מצמצום הבעיה לשיפור מדד תוצאה מהותי בעולם האתגר. נדרשת תרומה, לא בלעדיות |
| שרשרת השפעה | חמש חוליות בשער 2: בעיה ← שינוי ישיר ← השפעת ביניים ← תוצאה בעולם האתגר ← מדד תוצאה |
| Outcome / Output | Outcome הוא שינוי במצב הנפגעים או במערכת; Output הוא היקף פעילות או תפוקה, ואינו מספיק לבדו |
| ציון ריק (`null`) | אין בסיס להערכת קריטריון. אינו 0 ואינו ציון נמוך, מוצג כ"לא ניתן להעריך" וחוסם ציון משוקלל ורצועה |
| ציון שברירי | ציון מספרי שנשען על ראיה מוגבלת. סימון בלבד, ללא שינוי בציון או בחישוב |
| ערך מוסף של המטה | מה צפוי להתקדם בזכות NIIA שלא היה מתקדם, או שהיה מתקדם לאט יותר ובהיקף קטן יותר, בלעדיו (`niia_additionality`) |
| Domain Lead | מנהל אירוע הבעיה במפעל הבעיות — מחזיק ה-Ecosystem; תחת ה-COO (תפעול, אימפקט ופורטפוליו) |
| Domain Expert | מומחה חיצוני שמצטרף אד-הוק |
| Management Layer | שכבת ההחלטות הניהוליות מעל לאלגוריתם |
| Funnel Review | סקירה תקופתית של בריאות המשפך |
| ג'וקר | מנגנון חריגה במעבר ממפעל הבעיות להגדרת מיזם: בעיה עם פוטנציאל מערכתי שטרם נוסח, מאושרת לתעדוף גם ללא עמידה מלאה בקריטריונים הרגילים — באישור ניהולי מפורש. דגל מכני לדיון: כל ציוני האסטרטגי ≥4, וגם גודל האוכלוסייה או חומרת הבעיה = 1 |
| Human in the Loop | כל החלטה של אג'נט כפופה לאישור אנושי |
| מהימן לחלוטין | רמת מהימנות מידע: מקור ממסדי מוכר, ניתן להישען עליו ללא תיקוף נוסף |
| דורש סימוכין | רמת מהימנות מידע: טרם אומת — האייג'נט מצרף מקור/ראיה, אדם מאמת ומסווג |
| מידע שיצרנו | רמת מהימנות מידע: תוכן שנוצר בתוך המערכת עצמה — לא מחקרי/מתוקף, אך ניתן לחיפוש בדגל מפורש |
| מידע מתוקף (Ingestion) | מידע מהימן לחלוטין, או שאומת אנושית — שכל המערכת (ניקוד, כרטיסי בעיה) נשענת עליו |

מונחי שלב הגדרת המיזם וה-Business Wiki מרוכזים בקבצים המקבילים שם, כדי לשמור על "מונח אחד = הגדרה אחת" ליד ההקשר שבו הוא נוצר.
