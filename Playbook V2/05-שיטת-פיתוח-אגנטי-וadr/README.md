# נספח: שיטת פיתוח אג'נטי ו-ADR

> מבוסס על מתודולוגיית שטראוס אסטרטגיות לטרנספורמציה AI-Native (הוצג לביטוח לאומי, יולי 2026). **זהו נספח טכני חוצה-שלבים, לא שלב ממוספר בכור ההאצה** — הוא רלוונטי כשה[MVP/POC](../03-mvp-poc/README.md) או ה[Scale](../04-pmf-production-scale/README.md#תת-שלב-ג--scale-for-impact) כוללים בנייה/שדרוג של מערכת ליבה טכנולוגית (ובפרט טרנספורמציה של מערכות Legacy), לא בכל מיזם.

## איפה זה נכנס בתהליך?

לאחר ש[Roadshow](../02-הגדרת-המיזם/05-roadshow-ובחירת-שותפים.md) הצליח ושותף מוביל חתם, ולפני/במהלך בניית ה-[MVP/POC](../03-mvp-poc/README.md) — כשהמיזם כולל פיתוח טכנולוגי משמעותי אצל השותף/עם השותף. הפרק הזה מגדיר **איך** בפועל בונים ומתחזקים את הידע והקוד, כך שהמערכת שנבנית באמת AI-Native ולא רק "AI מוזרק לתהליך ישן". עקרון ה-Wiki שעומד בבסיס זה מוסבר כבר ב[תפיסת-ה-wiki](../00-חזון-ועקרונות/תפיסת-ה-wiki.md).
